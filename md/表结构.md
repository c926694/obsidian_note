# RCS 数据库表结构说明

> 结构来源：`common/db/migrations/` 下的迁移文件（`NNN_描述.sql`，001 起，当前到 111）与现场库导出的 `public.sql`。
> 本说明按现场库 public schema 的 66 张 `rcs_` 前缀表逐张核对列名与列注释写成；列名、表名一律保持英文原名。

## 迁移机制

- 迁移文件命名 `NNN_描述.sql`（3 位零填充），放 `common/db/migrations/`
- 每个 rpc 服务启动时经 advisory lock 串行执行；已执行的文件（按完整文件名记于 `rcs_platform_schema_migration`）跳过
- 修改已经执行过的迁移文件不会生效；结构变更必须新增迁移文件

## 一、平台与迁移域

### 1. rcs_platform_schema_migration —— 迁移版本记录

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| version | varchar(128) | 否 | 主键，完整迁移文件名（如 001_vda_schema.sql） |
| applied_at | timestamptz | 否 | 应用时间（默认当前时间） |

键：PK(version)。

## 二、审计与告警域

### 2. rcs_audit_event —— 审计事实流水

只追加不修改的「发生了什么」全量日志；业务关联列刻意无外键（审计写入不能被引用完整性阻塞）。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| id | varchar(128) | 否 | 主键，事件 ID（调用方提供） |
| occurred_at | timestamptz | 否 | 发生时间 |
| kind | varchar(64) | 否 | 事件类别（CONTROL_OPERATION 等） |
| actor / reason | varchar(255) / text | 可 | 操作主体 / 原因 |
| business_task_id / transport_order_id / vda_order_id / vehicle_id | varchar(255) | 可 | 业务关联标识 |
| summary | jsonb | 否 | 事件载荷（格式随 kind） |

键：PK(id)；索引含 jsonb 部分索引（summary->>'result'、summary->>'transactionId'、summary->>'sessionId'）。

### 3. rcs_audit_active_alert —— 活动告警投影

当前「还挂着」的告警，按 alert_key 归并一行一条。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| alert_key | varchar(1024) | 否 | 主键，告警归并键 |
| code | varchar(128) | 否 | 告警码 |
| message | varchar(512) | 否 | 告警内容 |
| first_seen_at / last_seen_at | timestamptz | 否 | 最早/最近发现时间 |
| occurrences | integer | 否 | 出现次数（CHECK > 0；重激活后清零重计） |
| business_task_id / transport_order_id / vda_order_id / vehicle_id | varchar(255) | 可 | 业务关联 |
| status | varchar(32) | 否 | 处置状态（默认 ACTIVE；CHECK 锁 ACTIVE/ACKNOWLEDGED/RESOLVED/CLOSED） |
| assignee | varchar(255) | 可 | 处置人（确认时写入） |
| acknowledged_at / resolved_at / closed_at | timestamptz | 可 | 三个处置时间戳 |
| last_actor | varchar(255) | 可 | 最近操作痕迹 |
| last_reason | text | 可 | 最近操作原因 |

键：PK(alert_key)；索引 (last_seen_at DESC, alert_key)。

### 4. rcs_audit_alert_lifecycle_event —— 告警处置账本

告警生命周期的处置流水（触发、确认、解决、关闭），只追加。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| alert_key | varchar(1024) | 否 | 归属告警（FK → rcs_audit_active_alert） |
| sequence | integer | 否 | 事件序号（CHECK > 0；复合主键 (alert_key, sequence)） |
| action | varchar(32) | 否 | 账本动作（CHECK 锁 RAISED/ACKNOWLEDGED/RESOLVED/CLOSED） |
| from_status | varchar(32) | 可 | 变更前状态（首条 RAISED 为空） |
| to_status | varchar(32) | 否 | 变更后状态 |
| actor / assignee | varchar(255) | 可 | 操作主体 / 处置人 |
| reason | text | 可 | 原因 |
| occurred_at | timestamptz | 否 | 发生时间 |

键：PK(alert_key, sequence)，FK(alert_key)；索引 (occurred_at, alert_key, sequence)。

### 5. rcs_audit_migration_run —— 审计导入批次台账

一批一次导入。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| migration_id | varchar(128) | 否 | 主键，迁移批次 ID |
| applied_at | timestamptz | 否 | 应用时间（默认当前时间） |
| rolled_back_at | timestamptz | 可 | 回退时间（未回退为空） |
| actor | varchar(255) | 否 | 操作主体 |
| manifest_sha256 | char(64) | 否 | 清单哈希 |

键：PK(migration_id)。

### 6. rcs_audit_migration_item —— 审计导入明细

批内每条明细。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| migration_id | varchar(128) | 否 | 归属批次（FK → rcs_audit_migration_run） |
| record_type | varchar(16) | 否 | 记录类别（CHECK 锁 ENTRY=rcs_audit_event / ALERT=rcs_audit_active_alert） |
| record_id | varchar(1024) | 否 | 记录 ID |
| content_sha256 | char(64) | 否 | 内容摘要 |
| action | varchar(16) | 否 | 处置动作（CHECK 锁 INSERTED/SKIPPED_SAME，内容相同则跳过） |
| rolled_back_at | timestamptz | 可 | 回退时间 |

键：PK(migration_id, record_type, record_id)，FK(migration_id)。

## 三、任务域

### 7. rcs_task_state —— 任务状态投影

一行一个任务，当前 business_state 加乐观锁 version。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| business_task_id | uuid | 否 | 主键（服务端生成 uuidv7） |
| request_id | varchar(128) | 可 | 调用方幂等标识（UNIQUE，重复命中幂等） |
| transport_order_id | varchar(255) | 可 | openTCS 运输订单标识（UNIQUE） |
| vda_order_id | varchar(255) | 可 | VDA 5050 订单标识 |
| vehicle_id | varchar(255) | 可 | 目标车辆 |
| business_state | varchar(32) | 否 | 业务状态（CHECK 锁 9 值英文枚举 PENDING/ACCEPTED/DISPATCHING/EXECUTING/PAUSED/EXCEPTION/COMPLETED/FAILED/CANCELLED） |
| dispatch_state | varchar(32) | 可 | 调度状态 |
| vehicle_state | varchar(64) | 可 | 车辆状态 |
| last_vehicle_observed_at | timestamptz | 可 | 最近观测时间 |
| profile_version | varchar(255) | 可 | 车辆档案版本（对应 VEHICLE_PROFILES 文档 revision） |
| control_owner | varchar(32) | 可 | 控制所有者（CHECK 锁 LEGACY_RCS/OPEN_TCS/MANUAL） |
| pending_operation | jsonb | 可 | 待处理操作 |
| version | integer | 否 | 乐观锁版本（默认 0；CHECK >= 0；每次流转 +1） |
| created_at / updated_at | timestamptz | 否 | 创建/更新时间 |
| action_transport_order_ids | jsonb | 否 | 派单动作关联的运输订单（默认 {}；CHECK object） |
| action_dispatch_facts | jsonb | 否 | 派单事实（默认 []；CHECK array） |
| action_execution_facts | jsonb | 否 | 执行事实（默认 []；CHECK array） |

键：PK(business_task_id)，UNIQUE(request_id)，UNIQUE(transport_order_id)；索引 (vda_order_id)、(vehicle_id, updated_at DESC)。

### 8. rcs_task_state_event —— 任务状态事件账本

状态流转历史（before/after 链），只追加。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| task_state_id | uuid | 否 | 归属任务（FK → rcs_task_state；复合主键 (task_state_id, sequence)） |
| sequence | integer | 否 | 事件序号（CHECK > 0；服务端行锁下 MAX+1 分配） |
| before_state | varchar(32) | 可 | 变更前状态（首条为空） |
| after_state | varchar(32) | 否 | 变更后状态（CHECK 锁 9 值英文枚举，与 rcs_task_state 同） |
| source | varchar(32) | 否 | 触发通道（API/MQTT 等） |
| action | varchar(16) | 可 | 处置动作（ACCEPT/DISPATCH 等 9 值） |
| reason | text | 可 | 流转原因 |
| actor | varchar(255) | 可 | 操作主体 |
| request_id | varchar(128) | 可 | 幂等标识 |
| occurred_at | timestamptz | 否 | 发生时间 |

键：PK(task_state_id, sequence)，FK(task_state_id)；索引 (occurred_at DESC)、(request_id)。

### 9. rcs_task_command_ledger —— 调 openTCS 的命令账本

RCS 给 openTCS 下发指令的记录（每任务一条当前命令，附提交状态）。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| business_task_id | uuid | 否 | 主键，归属任务 |
| request_id | varchar(128) | 可 | 幂等标识（UNIQUE） |
| command | jsonb | 否 | 命令载荷 |
| command_fingerprint | char(64) | 否 | 命令内容指纹 |
| actor | varchar(255) | 可 | 下发主体 |
| transport_order_id | varchar(255) | 可 | 运输订单（UNIQUE） |
| submission_state | varchar(16) | 否 | 提交状态（CHECK 锁 PENDING/ACCEPTED/FAILED） |
| submission_attempts | integer | 否 | 提交尝试次数（默认 0；CHECK >= 0） |
| last_error | text | 可 | 最近一次错误 |
| control_transaction_id | varchar(128) | 可 | openTCS 事务号（部分唯一索引，非空时唯一） |
| created_at / updated_at | timestamptz | 否 | 时间戳 |

键：PK(business_task_id)；索引 (submission_state, updated_at)。

## 四、控制面域

### 12. rcs_control_plane_document —— 控制面文档（revision 链）

车辆档案、地图包、绑定关系等配置文档；同 key 只追加 revision，不物理覆盖。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| document_type | varchar(64) | 否 | 文档类别（复合主键之一；7 类：VEHICLE_PROFILES/MAP_PACKAGES/VEHICLE_MAP_BINDINGS/FAT_RELEASES/FORKLIFT_ACTION_TEMPLATES/PRODUCTION_FAT_SESSIONS/SEER_G4_RELEASES） |

| revision | integer | 否 | 修订号（CHECK > 0，从 1 递增） |

| content_sha256 | char(64) | 否 | 内容摘要（同内容不产生新 revision 的判据） |
| source_ref | varchar(2048) | 可 | 来源引用 |
| migration_id | varchar(128) | 可 | 迁移批次 ID |
| created_at / updated_at | timestamptz | 否 | 时间戳 |

键：PK(document_type, document_id)；部分唯一索引约束各类文档同一时刻只有一份在用的绑定/会话（按 content 里的键）。

## 十、编排域（rcs-orchestrator）

> 本域五张表都由同一个服务 `rcs-orchestrator`（编排服务）维护，按业务分四块：
> 场景模板（`rcs_scene` / `rcs_scene_notify`）、第三方地址（`rcs_third_party`）、车体机构档案（`rcs_mechanism_profile`）、任务组与子任务（`rcs_task_group` / `rcs_task`）。
> 四块共用一条服务链路：前端 → gateway-api → rcs-orchestrator → PostgreSQL（模板 JSON 另存文件）；派车执行由 `rcs-dispatch` 承担。
> 接口文档：四块合并在《编排服务接口文档》（`orchestrator.md`）里，分「二、业务场景模板域」「三、第三方地址域」「四、任务组域」「五、车体机构档案域」。

### 57. rcs_scene —— 业务场景配置（任务执行配方）

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| id | bigint 自增 | 否 | 主键（IDENTITY） |

说明：模板 JSON 原文存在本地文件 `data/scenes/{scene_code}.json`（覆盖式、原子写），本表只存元信息与 `template_url`；前端拼自己的后端地址下载模板回显。创建只建元信息空壳（template_url 为空 = 还没配模板），模板由 `PUT /api/scenes/:id/template` 单独提交；保存模板时同步重建本场景的通知索引（见 rcs_scene_notify）；场景编码改名时模板文件跟随改名、索引跟随迁移。模板有三代形态（v1 的 `segments` 与 `points`、v2 的段内动作与高度、v5 的 `actions` 动作清单与 `edges` 出线），字段与校验规则见《场景模板字段说明》与《编排服务接口文档》（`orchestrator.md`）的「二、业务场景模板域」。场景模板里还带车体配置（vehicles[] 与 actions 的动作序列映射），建组时快照进 `rcs_task_group.vehicle_conf`。

| actions | jsonb | 可 | 段机构动作序列（jsonb 数组，顺序即执行顺序）：元素 {"at":"START|END","type":"SET_HEIGHT|REACH_OUT|...","height_mm":0,"position":0} |

| control_method | varchar(16) | 可 | 通讯控制方式：VDA 下发（RCS 派车执行）/ HTTP 调度第三方（空 = 按 VDA 处理，兼容老任务） |

| lock_vehicle | boolean | 可 | 是否锁定车（动作级）：本动作派定车后锁到任务组结束，组内后续动作强制用它，其它任务与回休息位不得占用；NULL = false |
| allow_switch_vehicle | boolean | 可 | 是否允许任务换车（动作级，仅组内首个动作生效）：车还没到任务起点时，因异常或更合适的车自动换车；NULL = false |

## 十一、调度域

### 62. rcs_dispatch_run —— 调度在途记录

一个子任务在车端跑起来后，这里保存订单号、地图、分段路线与进度；服务重启后按 order_id 加车端 lastNodeId 判断进度并接着放行，排查时也能直接看到这台车这条任务切成了几段、当前在第几段。

| 列 | 类型 | 可空 | 说明 |
|---|---|---|---|
| id | bigint 自增 | 否 | 主键（IDENTITY） |
| task_code | varchar(128) | 否 | 任务单号（唯一；一个任务同时只有一条在途记录） |
| agv_code | varchar(64) | 否 | 执行车辆编号 |
| map_code | varchar(50) | 否 | 任务所在拓扑地图编号 |
| order_id | varchar(128) | 否 | 下发给车端的 VDA 订单号 |
| order_update_id | integer | 否 | 订单更新序号（每次重发或更新递增；默认 0） |
| route_codes | text | 否 | 整条规划路线（点位编码串） |
| segments | jsonb | 否 | 分段路线（每段的起终点与经过点，调度按段放行与加锁） |
| current_segment | integer | 否 | 当前执行到第几段（默认 0） |
| state | varchar(16) | 否 | 在途状态：RUNNING 执行中 / STOPPING 已发取消单等车停稳 / DONE 完成 / FAILED 失败 / YIELDED 环路让行（已放掉段锁并把任务退回待下发，等退避到点重新派发） |
| last_error | text | 可 | 最近一次错误 |
| created_at / updated_at | timestamptz | 否 | 创建 / 更新时间（默认当前时间） |

键：PK(id)，UNIQUE(task_code)；索引 idx_rcs_dispatch_run_state(state)。
